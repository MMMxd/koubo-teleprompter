# 口播工坊 · 踩坑与经验（2026-11-12 沉淀）

全部来自本项目真实事故：每一條都经过「复现 → 定位 → 修复 → 回归验证」闭环。新会话开工前先读一遍，能省数小时。

---

## 一、构建系统

### 1. AGP 8.x 默认不再生成 BuildConfig
- **症状**：`Unresolved reference: BuildConfig`，引用 `BuildConfig.VERSION_NAME` 直接编译失败。
- **修复**：`android { buildFeatures { buildConfig = true } }`。
- **教训**：AGP 8 升级后凡是引用 BuildConfig 的老代码都会炸；需要密钥/版本号注入时显式开启。

### 2. 密钥进仓库 = 事故
- LLM API Key 曾硬编码在 `Llm.kt`。入库前迁移：`local.properties`（git-ignore）存 `llmKey=...`，`build.gradle` 读入 `buildConfigField "String","LLM_KEY",...`，代码引用 `BuildConfig.LLM_KEY`。
- **铁律**：入库前全仓 grep `sk-[a-zA-Z0-9]{20,}` 一遍。

### 3. Kotlin R 常量内联 + 增量编译 = 资源 ID 错位闪退
- **症状**：改版后 `findViewById(R.id.xxx)` 返回 null → NPE 闪退，但布局文件里控件明明存在；clean 后依然复现（本项目曾误判为缓存）。
- **根因**：Kotlin 会把 R 常量内联进 class 文件；大量增删资源后 ID 全表洗牌，增量编译不重编未改动的类 → 运行时用旧 ID 找新布局。
- **修复**：大改资源后 **clean 全量重编**。
- **真正的元凶往往在代码**：本项目启动闪退的真根因是布局改版后 `DraftVH` 仍绑定已删除的 `R.id.meta`（返回 null，Kotlin 非空检查抛 NPE）。**排查顺序：先 grep 布局里 id 是否还存在，再怀疑缓存。**
- **布局改版自检清单**：改布局后必须 `grep -rn "R.id." app/src` 对照新布局逐一确认每个 id 还存在、类型一致（TextView→Button 的强转也会 ClassCastException）。

## 二、Android 兼容性

### 4. Android 16 上 SwitchCompat 必崩（OnePlus 实机）
- **症状**：`SwitchCompat.onMeasure → makeLayout → StaticLayout NPE`（无文字开关触发）。
- **修复**：自制 `PillToggle`（纯 TextView 胶囊开关）全量替换。
- **教训**：appcompat 老组件在最新系统上随时可能炸；自绘简单控件比追兼容补丁稳。

### 5. PillToggle 初版自引用 NPE
- `val view = TextView(ctx).apply { ... render() }`——render() 里引用 `view.text`，此时 view 尚未赋值完成。
- **修复**：首渲染挪进 `init {}` 块（属性赋值完成后执行）。

### 6. 悬浮窗按钮"点不动"：工厂函数收了 onClick 参数但没接 setOnClickListener
- 传参 ≠ 接线。**自检清单：凡是传回调参数的工厂函数，构建完必须真机点一遍。**

### 7. 语音跟随闪退（无声、无堆栈、crash.txt 空）
- **症状**：点跟随 → 进程直接死。无 AndroidRuntime 异常、无 tombstone、crash 缓冲区为空。
- **根因**：sherpa-onnx C++ 在模型加载校验失败时**直接 `exit(255)`**（`Zygote: Process exited cleanly (255)`）——不走 Java 异常、不走 tombstone，任何 try/catch 与崩溃捕获器都拦不住。
- **根因链**（三层）：
  1. 2023 年的 `zipformer-zh-14M` transducer 模型与 2025 年的 sherpa-onnx 2.0.1 运行时不兼容（InitEncoder 校验失败即自杀）；
  2. assets 直读模型（AAssetManager）在部分系统上不可靠；
  3. aapt 默认压缩 assets，native 层按文件描述符直读会失败。
- **修复**（三管齐下）：
  - 换与运行时**同代**的官方模型（`streaming-zipformer-small-ctc-zh-int8-2025-04-01`，26MB 单文件 CTC）；
  - 首次启动把模型复制到 `filesDir` 按**文件路径**加载（Kotlin 侧 `OnlineRecognizer(assetManager = null, config = cfg)`，null 走文件路径）；
  - `androidResources { noCompress += ['onnx','txt'] }`。
- **架构级防御**：识别引擎整体搬进 **`:speech` 独立进程**（`FollowService`）。native exit 只死识别进程，悬浮窗/提词页安然无恙；UI 侧 12 秒收不到心跳 → 提示「引擎异常退出」→ 重新点跟随即全新重试。
- **教训**：**会调用 exit/abort 的第三方 native 库，必须进独立进程**。文件完整性用 HEAD 请求对官方仓库比 Content-Length。

### 8. 手动写稿页 ClassCastException
- 布局把 `<Button>` 改成 `<TextView>` 后，代码 `findViewById<Button>` 强转崩溃。
- **教训**：改布局控件类型时，同步 grep 代码里的强转/类型声明。同一事故家族：布局删除 `meta` 控件后代码残留 `R.id.meta` 绑定 → 启动闪退（本项目最严重的一次线上事故）。

## 三、sherpa-onnx 专项

- 模型选型：`streaming-zipformer-small-ctc-zh-int8-2025-04-01`（26MB 单文件，中文，2025 同代）。
- Kotlin API：`OnlineRecognizer(assetManager = null, config = cfg)`——**首参可空，null = 文件路径加载**；传 config 位置参数会塞进 assetManager 槽位报类型错。
- CTC + BPE 分词模型需三件套：`model.int8.onnx` + `tokens.txt` + `bbpe.model`，配置 `zipformer2Ctc` + `modelingUnit="bpe"` + `bpeVocab=路径`。
- 模型完整性验证：对 HF 仓库发 HEAD 请求比 Content-Length（下载截断会直接引发 7 号问题）。
- 引擎日志的 `query_head_dims does not exist` 是 zipformer 模型的正常警告，不是错误。

## 四、UI 交互约定（用户实锤反馈）

- 速度滑条：**0.02~8.0 行/秒**（0.5 起步被嫌快）；全屏/悬浮窗两处联动。
- 手动拖动提词文本松手后**必须自动恢复滚动**（只在手指按下期间暂停）。
- ＋ 是**动作按钮**不占导航位：点击直接开写稿页；导航栏只留 稿件/热点/我的，各二级页自带同款导航栏且顺序必须一致。
- 悬浮窗形态：正文即窗口，⚙ 展开「滚动/速/字/透/高/跟随」，✕ 大红钮关闭；**「高」滑条拉长拉短窗体**（25%~80% 屏高，实时生效并记忆）。
- 跟随交互：未授权麦克风 → 引导去应用详情；引擎未就绪 → 状态条「加载识别模型…」；就绪 → 「跟随已开启：念到哪滚到哪」+ 当前句琥珀高亮 + 按钮变「暂停」。

## 五、工程流程（本机实测）

- **模拟器工作流**（免真机安装迭代）：`emulator -avd koubo -no-window -no-snapshot`（每次冷启动，状态可控）→ uiautomator dump 拿精确坐标驱动 UI → `adb exec-out screencap -p > 文件` 在 PowerShell 下会二进制损坏，**必须 `screencap 到设备再 adb pull`** → 每步截图审阅。
- `adb shell wm size` 在 headless 模拟器下返回值不可信（曾报 1080x1080，实为 1080x2400），**坐标以 screencap 实际分辨率推算**。
- 授权免手工：`pm grant ... RECORD_AUDIO`、`appops set ... SYSTEM_ALERT_WINDOW allow`。
- uiautomator dump **看不见 Service 悬浮窗的内部视图**（只见底下的 Activity），悬浮窗交互测试改用截图坐标推算。
- PowerShell 5.1 三坑：命令/脚本里的中文必乱码（脚本纯英文最稳）；无 BOM 的 .ps1 中文必炸；`adb exec-out` 重定向会 UTF-16 化二进制。
- 网络：dl.google.com / repo1.maven 直连 ✓；GitHub 走 gh-proxy 系镜像（部分资源 404 就换一个镜像头）；HF 走 hf-mirror.com ✓；模型完整性用 HEAD 比 Content-Length。
- 悬浮窗被 ColorOS/OnePlus 限制：引导用户「应用详情 → 解除限制」+ App 内两步引导对话框。
